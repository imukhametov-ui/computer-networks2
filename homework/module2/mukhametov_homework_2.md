## Завдання 1. Аналіз відкритих портів (2 бали)

**Команда:**

```bash
ss -tuln
```

### Результат виконання

```text
Netid  State   Recv-Q  Send-Q  Local Address:Port   Peer Address:Port
udp    UNCONN  0       0       224.0.0.251:5353    0.0.0.0:*
udp    UNCONN  0       0       0.0.0.0:5353        0.0.0.0:*
udp    UNCONN  0       0       0.0.0.0:51307       0.0.0.0:*
udp    UNCONN  0       0       127.0.0.53%lo:53    0.0.0.0:*
udp    UNCONN  0       0       [::]:5353           [::]:*
udp    UNCONN  0       0       [::]:60287          [::]:*
tcp    LISTEN  0       128     0.0.0.0:22          0.0.0.0:*
tcp    LISTEN  0       128     127.0.0.1:631       0.0.0.0:*
tcp    LISTEN  0       4096    127.0.0.53%lo:53    0.0.0.0:*
tcp    LISTEN  0       128     [::]:22             [::]:*
tcp    LISTEN  0       128     [::1]:631            [::]:*
```

### Аналіз відкритих портів

| Протокол | Порт | Стан | Призначення |
|---|---|---|---|
| TCP | 22 | LISTEN | SSH — віддалений доступ |
| TCP | 631 | LISTEN | CUPS — служба друку |
| TCP | 53 | LISTEN | DNS — локальне перетворення доменних імен |
| UDP | 53 | UNCONN | DNS — обробка запитів |
| UDP | 5353 | UNCONN | mDNS — локальне виявлення мережевих служб |

### Пояснення

Команда `ss -tuln` показує TCP- та UDP-сокети, які очікують на з'єднання або приймання мережевих даних.

Параметри команди:
- `-t` — TCP;
- `-u` — UDP;
- `-l` — прослуховування портів;
- `-n` — числове відображення адрес і портів.

Для TCP використовується стан `LISTEN`, який означає очікування вхідних з'єднань.

Для UDP використовується стан `UNCONN`, оскільки UDP є протоколом без встановлення з'єднання.

Порт `22` використовується службою SSH, порт `631` — службою друку CUPS, а порт `53` — для DNS.

Адреса `127.0.0.1` означає, що служба доступна лише через локальний інтерфейс. Адреса `0.0.0.0` означає прив'язку до всіх локальних IPv4-інтерфейсів.

**Висновок:** в Ubuntu виявлено кілька активних TCP- та UDP-портів. Їхній стан і призначення проаналізовано.
## Завдання 2. Аналіз процесів, що слухають порти (2 бали)

**Команда:**

```bash
sudo ss -tulpn
```

### Результат виконання

```text
udp UNCONN 224.0.0.251:5353 users:(("chrome",pid=2101,fd=33))
udp UNCONN 0.0.0.0:5353 users:(("avahi-daemon",pid=579,fd=12))
udp UNCONN 0.0.0.0:51307 users:(("avahi-daemon",pid=579,fd=14))
udp UNCONN 127.0.0.53%lo:53 users:(("systemd-resolve",pid=379,fd=13))
udp UNCONN [::]:5353 users:(("avahi-daemon",pid=579,fd=13))
udp UNCONN [::]:60287 users:(("avahi-daemon",pid=579,fd=15))
tcp LISTEN 0.0.0.0:22 users:(("sshd",pid=730,fd=3))
tcp LISTEN 127.0.0.1:631 users:(("cupsd",pid=736,fd=7))
tcp LISTEN 127.0.0.53%lo:53 users:(("systemd-resolve",pid=379,fd=14))
tcp LISTEN [::]:22 users:(("sshd",pid=730,fd=4))
tcp LISTEN [::1]:631 users:(("cupsd",pid=736,fd=6))
```

### Аналіз процесів

| Процес | PID | Порт | Протокол |
|---|---|---|---|
| sshd | 730 | 22 | TCP |
| cupsd | 736 | 631 | TCP |
| systemd-resolve | 379 | 53 | TCP/UDP |
| avahi-daemon | 579 | 5353 | UDP |
| chrome | 2101 | 5353 | UDP |

### Пояснення

Команда `ss -tulpn` дозволяє визначити мережеві порти та процеси, які їх використовують.

Параметр `-p` показує інформацію про процеси, зокрема їхні назви та PID. Команда виконана з `sudo`, щоб отримати доступ до інформації про системні служби.

У результаті встановлено:

1. **sshd (PID 730)** — прослуховує TCP-порт 22 і забезпечує віддалене підключення через SSH.
2. **cupsd (PID 736)** — використовує TCP-порт 631 для роботи системи друку CUPS.
3. **systemd-resolve (PID 379)** — використовує TCP та UDP на порту 53 для локальної обробки DNS-запитів.
4. **avahi-daemon (PID 579)** — використовує UDP-порт 5353 для виявлення служб у локальній мережі через mDNS.
5. **chrome (PID 2101)** — використовує UDP-сокет на порту 5353 для локального мережевого виявлення.

### Висновок

За допомогою команди `sudo ss -tulpn` визначено процеси, які використовують мережеві порти Ubuntu. Встановлено зв'язок між назвами процесів, їхніми PID, транспортними протоколами та номерами портів.
## Завдання 3. Перевірка TCP-з'єднання (2 бали)

**Команда:**

```bash
nc -vz google.com 80
```

### Результат виконання

```text
Connection to google.com (142.251.98.101) 80 port [tcp/http] succeeded!
```

### Аналіз результату

| Параметр | Значення |
|---|---|
| Домен | google.com |
| IP-адреса сервера | 142.251.98.101 |
| Транспортний протокол | TCP |
| Порт | 80 |
| Служба | HTTP |
| Результат | З'єднання успішно встановлено |

### Пояснення

Команда `nc -vz google.com 80` перевіряє можливість встановлення TCP-з'єднання з сервером Google через порт 80.

Параметр `-v` вмикає детальне відображення результату, а `-z` перевіряє доступність порту без передавання прикладних даних.

Повідомлення `succeeded!` підтверджує успішне встановлення TCP-з'єднання.

TCP — протокол транспортного рівня (рівень 4 моделі OSI), який забезпечує надійну передачу даних із контролем порядку та повторною передачею втрачених сегментів.

**Висновок:** TCP-порт 80 сервера Google доступний, з'єднання встановлено успішно. Перевірка підтвердила доступність TCP-служби, але не перевіряла отримання HTTP-відповіді.

## Завдання 4. Порівняння TCP та UDP (3 бали)

**Команди:**

```bash
nc -vz -w 5 8.8.8.8 53
nc -u -vz -w 5 8.8.8.8 53
```

### Результати виконання

**TCP:**

```text
Connection to 8.8.8.8 53 port [tcp/domain] succeeded!
```

**UDP:**

```text
Connection to 8.8.8.8 53 port [udp/domain] succeeded!
```

### Порівняння результатів

| Характеристика | TCP | UDP |
|---|---|---|
| Протокол | TCP | UDP |
| IP-адреса | 8.8.8.8 | 8.8.8.8 |
| Порт | 53 | 53 |
| Результат команди | succeeded | succeeded |
| Встановлення з'єднання | Так | Ні |
| Підтвердження доставки | TCP підтверджує отримання даних | UDP не має вбудованого підтвердження |
| Гарантія порядку доставки | Так | Ні |

### Пояснення

TCP (Transmission Control Protocol) — транспортний протокол із встановленням з'єднання. Перед передаванням даних використовується триетапне рукостискання (three-way handshake): SYN → SYN-ACK → ACK.

Команда `nc -vz -w 5 8.8.8.8 53` підтвердила успішне встановлення TCP-з'єднання з DNS-сервером Google через порт 53.

UDP (User Datagram Protocol) — транспортний протокол без встановлення з'єднання. Він не використовує триетапне рукостискання та не забезпечує вбудованих механізмів гарантованої доставки, повторної передачі або впорядкування пакетів.

Команда `nc -u -vz -w 5 8.8.8.8 53` також повернула `succeeded!`. Проте для UDP цей результат не гарантує отримання пакета віддаленим сервером або наявності відповіді.

### Висновок

Обидві перевірки завершилися повідомленням `succeeded!`, але їхні результати мають різне значення.

TCP підтвердив встановлення транспортного з'єднання, тоді як UDP не передбачає встановлення з'єднання. Для достовірної перевірки роботи DNS через UDP необхідно надіслати коректний DNS-запит та отримати відповідь.

## Завдання 5. DNS-резолвінг (3 бали)

**Команда:**

```bash
nslookup github.com
```

### Результат виконання

```text
;; communications error to 127.0.0.53#53: timed out
Server:         127.0.0.53
Address:        127.0.0.53#53

Non-authoritative answer:
Name:    github.com
Address: 140.82.121.3
```

### Аналіз DNS-відповіді

| Параметр | Значення |
|---|---|
| Доменне ім'я | github.com |
| IPv4-адреса домену | 140.82.121.3 |
| DNS-сервер | 127.0.0.53 |
| Порт | 53 |
| Тип відповіді | Non-authoritative |
| Результат | DNS-резолвінг завершився отриманням IP-адреси |

### Пояснення

DNS (Domain Name System) — система доменних імен, яка дозволяє перетворювати зрозумілі людині доменні назви на IP-адреси.

Команда `nslookup github.com` надіслала DNS-запит для визначення IP-адреси домену `github.com`.

Система використовувала локальний DNS-резолвер `127.0.0.53`, який працює через службу `systemd-resolved`.

Під час виконання з'явилося повідомлення `timed out`, що свідчить про відсутність своєчасної відповіді на одну зі спроб запиту. Проте IP-адресу домену вдалося отримати.

Відповідь `Non-authoritative answer` означає, що інформацію надав не авторитетний DNS-сервер домену.

### Висновок

У результаті DNS-резолвінгу домен `github.com` було перетворено на IPv4-адресу `140.82.121.3`.

Незважаючи на початковий тайм-аут, DNS-запит завершився отриманням відповіді. Це демонструє роботу системи доменних імен та локального DNS-резолвера Ubuntu.
